## What This Is

Project management app positioned between Notion (flexible content) and a lightweight PM tool
(project structure, reminders, team access).

Core differentiator: project-scoped journal where everything is anchored to a project, a date, or both.
Closest reference product: Agenda.app -- this is the team version of that idea with full PM structure.

- Personal use first, architected to be sellable later (multi-team, multi-workspace)
- Desktop-first. Mobile via PWA wrapper (next-pwa) -- no separate native app
- App name: **Ruang** (Indonesian for "space/room") -- working name, not yet confirmed

## Data Hierarchy

```
Platform
└── Project
    └── Workstream
        └── Entry (polymorphic)
            ├── note
            ├── file
            ├── task
            ├── reminder
            └── link
```

### Critical data rule

`Entry` is a single polymorphic table. It uses a `type` text column and a `content` JSONB column
whose shape varies by type (see below).

Both `workstream_id` AND `project_id` are stored directly on every entry row -- even though a
workstream already belongs to a project. This is intentional: it enables Today View and Calendar
to query across projects without joins.

## Entry Types

### Shared fields on every entry

```
id, public_id, type, project_id, workstream_id, created_by,
pinned_date (date), pinned_date_end (date), tags (jsonb array, 1-3 labels),
content (jsonb), is_pinned, created_at, updated_at
```

### `note`

Full TipTap RTE. Content shape:
```json
{ "title": "", "tiptap_json": {}, "is_locked": false, "version_number": 1 }
```
- Blocks: H1-H3, paragraph, bullet list, numbered list, checklist (strikethrough on check),
  indentation, table, divider, callout block (colored + icon), code block
- Formatting: bold, italic, underline, strikethrough, superscript, subscript
- @mention sends in-app notification
- Version history: last 10-20 versions, revertible (stored in `note_versions` table)
- Export as PDF or plain text
- Note locking (prevent edits without unlocking)

### `file`

Content shape:
```json
{ "title": "", "description": "" }
```
- Actual file metadata lives in the `files` table (linked by `entry_id`)
- 20MB per file limit
- Preview: images inline, PDF embedded, video HTML5, others icon + download
- Download all files in project as ZIP
- NO file versioning -- re-upload under same entry to update

### `task`

Content shape:
```json
{ "title": "", "status": "todo", "due_date": null }
```
- Status values: `todo` / `in_progress` / `blocked` / `done`
- Status renders as a colored visual pill -- never a text dropdown
- Overdue tasks pulse visually
- Assignees stored in `entry_assignees` table (supports multiple)
- In-app notification only -- NO email for tasks

### `reminder`

Content shape:
```json
{
  "title": "",
  "type_label": "deadline",
  "schedule_type": "one_time",
  "scheduled_at": null,
  "recurrence": null,
  "audience_type": "just_me",
  "recipient_ids": []
}
```
- `type_label`: `deadline` / `follow_up` / `meeting` / `review` -- affects email template
- `schedule_type`: `one_time` / `recurring`
- `audience_type`: `just_me` / `all_members` / `specific`
- Email delivery via Resend; in-app notification bell (list, not popup)
- Delivery records tracked in `reminder_deliveries` table
- NO snooze from email link

### `link`

Content shape:
```json
{ "url": "", "title": "", "og_image": null, "og_description": null, "notes": "" }
```
- Auto-fetches OG metadata on save
- Optional short notes field

## Database

Full schema: `ruang_mvp_schema.sql`

All tables use:
- `id uuid` -- internal primary key (`gen_random_uuid()`)
- `public_id text` -- human-readable external ID generated by `generate_public_id(prefix)`,
  e.g. `usr_A1B2C3`, `ent_9F2E1A`

Key tables: `users`, `sessions`, `projects`, `project_members`, `invitations`,
`workstreams`, `entries`, `entry_assignees`, `note_versions`, `files`,
`reminder_deliveries`, `notifications`

## Auth and Roles

Google OAuth via NextAuth.js. "Remember me" toggle (persistent vs session-only).
Session timeout configurable per user (`session_timeout_minutes` on `users`).

**Global roles:**

| Role | Permissions |
|---|---|
| Admin | CRUD all users + all projects |
| Member | Create/manage own projects, invite others |
| Viewer | Read-only on shared projects |

Project-level permission override is possible (e.g. share with Viewer but allow comments).
Invite by email via Resend. Admin can also create accounts directly.

## Views

### Today View (default home screen)

Cross-project, cross-workstream aggregation of everything due or pinned to today.
Overdue items shown prominently. Grouped by project + workstream.
Gentle "Next Up" nudge for unscheduled items (text at bottom, not a popup).

### List View (default inside a project)

Chronological feed of all entries, grouped by date. Unscheduled entries float to top
as a collapsible "Unscheduled" section.

### Project Timeline Board (2nd most important view)

Custom CSS grid -- NOT FullCalendar. Key architecture:
- Left panel frozen: project/workstream tree, collapsible rows, color-coded by project
- Horizontal scrollable date columns (week view default; month/day toggle)
- Today column always highlighted in amber
- Entry chips per cell: type icon + truncated label
- Chip color logic:
  - note + file: tinted to project color
  - reminder: always amber
  - link: always purple
  - task: neutral
  - done task: green with strikethrough
- "+N more" badge when cell has more than 2 entries
- Hover empty cell: faint "+ pin here" affordance
- Click chip: opens full entry in side panel (not new page)
- Drag chip to new date: reschedules via dnd-kit
- Filter by: all projects / single project / entry type / workstream
- "Unscheduled" sidebar drawer for entries with no `pinned_date`

### Kanban View -- Phase 3 only

Status columns (To Do / In Progress / Blocked / Done). Drag between columns.

## ADHD-Friendly Design Rules

Apply these throughout -- they are product requirements, not optional polish:

1. Today View is always the default landing -- never a blank project list
2. Inbox / Brain Dump Zone: catch-all with zero required fields
3. Quick Capture FAB: always-visible floating button, pre-fills current project + today
4. Focus Mode per workstream: one click hides everything else
5. Color before text: project + workstream colors chosen by user
6. Visual status pills (never text dropdowns); overdue tasks pulse
7. No mandatory fields -- any entry only requires a title/name
8. "Next Up" nudge at bottom of Today View only
9. Compact chips in Calendar -- scan, don't read
10. Collapsed project rows in Timeline reduce cognitive load

## Do Not Build (Explicitly Cut -- Do Not Suggest)

- File versioning (re-upload under same entry instead)
- Snooze from email link in reminder emails
- Real-time collaborative editing (single-editor only)
- Activity log / audit trail
- External client access (internal team only)
- FullCalendar for the Timeline Board (use custom CSS grid only)
- Email notifications for tasks (in-app only)
